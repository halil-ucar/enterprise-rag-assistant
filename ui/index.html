Der Reranker hebt die schwerste Kategorie (Paraphrase, kein Wort-Überlapp) und repariert das Fusions-Rauschen bei Fehlercodes und Standorten — verschlechtert aber Versions-Zwillinge leicht (0.900 → 0.800): ein aktuelles Dokument und sein abgelöster Zwilling sehen für einen Cross-Encoder fast gleich aus. Genau solche Kompromisse macht die Ablation sichtbar.

Sicherheit

Sicherheit liegt in der Datenbank und im Code, nicht im Prompt. Datenklasse bestimmt das Modell-Routing; Row-Level Security filtert jede Query; Löschung ist eine getestete Kaskade.

Datenklassen-Routing
public→Cloud (OpenAI / Azure-EU)
internal→Cloud (OpenAI / Azure-EU)
confidential→Lokal (Ollama) — kein Cloud-Fallback

Deterministisch im Code erzwungen, fail-closed: Unklassifiziertes gilt als vertraulich; fällt der lokale Pfad aus, gibt es einen Fehler statt Cloud-Degradierung. Der gesamte Anfragepfad (Condensation, Routing, Generation) bindet die Policy.

Postgres RLS mit FORCE, eigene App-Rolle, SET LOCAL pro Transaktion — die Filterung gilt auch für die Vektorsuche. Fail-closed getestet: ohne gesetzten Kontext kommen null Zeilen zurück, nicht alle.

Löschkaskade — gelöscht heißt überall

Eine Löschung im Bereich Dokumente entfernt in EINER Operation die Chunks samt Vektoren, alle zitierenden Cache-Antworten, redigiert die zitierenden Sitzungsnachrichten und die Feedback-Zeilen — und erhöht die Korpus-Version, sodass auch rechnerisch mögliche Cache-Schlüssel ungültig werden. Diese Kaskade läuft bei jedem Push als Integrationstest in der CI.

Antworten stammen ausschließlich aus den hinterlegten Dokumenten und werden mit Quelle belegt.
